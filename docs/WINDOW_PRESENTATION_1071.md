# 1.0.71 Windows 毛玻璃与窗口呈现

## 问题与最终实现

最大化或接近满屏时，毛玻璃背景持续闪烁，文字和按钮稳定。本机用户已确认新版内核对照窗口恢复正常。

- Windows Electron 从 33.4.11 更新并固定到 44.3.0。新版内核负责同步 Chromium 内部透明状态、DWM 材质和窗口边框；正式实现沿用用户确认的这条路径。
- 删除旧版 helper 对窗口样式、最大化工作区、裁剪区域、DWM 属性和扩展客户区的强制改写。这些旧补丁在新内核上会干扰还原尺寸。
- 保留原有 260 ms 原生启动淡入。淡入完成后，helper 只清除属于本进程且 alpha=255 的启动分层标记；保留颜色键、分数透明度和鼠标穿透窗口，不调整位置、大小或材质。
- 窗口显示、还原和焦点事件合并排队，隐藏和最小化时延后清理，关闭时取消。Acrylic 不在每次窗口事件中重新安装。
- 保留硬件加速、WebGL、皮肤与页面动效。没有修改显卡驱动、系统 MPO/VRR 设置或全局透明度偏好。
- 分数 DPI 的尺寸换算在启动恢复时测量并有限次校正，不监听 resize 做反馈调整，避免重开后累积 1～2 像素的尺寸误差。
- Mac 发布命令与 CI 显式保留已验证的 Electron 33.4.11。44.3.0 在 Intel 云测试机出现 EGL/GPU 初始化失败，不能将 Windows 内核升级直接用于 Mac。未使用禁用硬件加速或降低皮肤渲染验收要求来绕过失败。

上游依据：[Electron PR 47386](https://github.com/electron/electron/pull/47386) 说明旧内核透明状态和 DWM 扩展客户区不同步的问题。使用官方 Electron 发行包，没有复制上游源代码到 KAMUCL。

## 验证

构建后用项目安装的 Electron 运行；使用独立临时配置，不访问用户账户、不启动或结束用户游戏。

```text
electron scripts/verify-window-controls.cjs
electron scripts/verify-window-presentation.cjs
electron scripts/verify-native-blur.cjs
```

- 窗口控制覆盖标题栏双击、最大化按钮、系统最大化、按钮连续切换、最小化恢复、还原尺寸与状态保存、双屏 125% DPI、负坐标屏幕。连续操作为原生动画留出 450 ms，标题栏消息单独验证。
- 原生模糊检查先切换自建纯黑/纯白背景证明透光，再切换 8 DIP 黑白条纹验证细节被模糊。单纯透光不能算毛玻璃验收通过。
- 持续呈现记录普通、97% 工作区和最大化尺寸的静态像素、窗口事件、动画回调以及实际 WebGL 渲染器。静态桌面截图无法覆盖物理显示器全部刷新行为，因此同时保留用户实际观察验收。
- 自动化测试覆盖事件合并、焦点节流、销毁取消、隐藏/最小化保护、原生错误隔离和淡入完成时序。

本机 RTX 5080 对照：黑白背景透光差约 37.67，细条纹区域差异为 0，真实模糊存在；用户确认最大化/接近满屏正常。旧 AccentState 3/4 虽停止闪烁但没有实际模糊，未采用。仅清理分层窗口的初始候选也未解决持续闪烁，未发布。

测试主窗口不得调用 setIgnoreMouseEvents(true)，该 API 会改变 WS_EX_LAYERED，污染验证。GUI 测试进程不得以 windowsHide:true 启动，否则首次 show 可能被系统隐藏。不要将动画回调速率当成游戏 FPS 或所有机器的性能承诺。

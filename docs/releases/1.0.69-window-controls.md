# v1.0.69 窗口操作修复

## 原因与实现

旧版 Windows 使用全局的“假最大化”状态，按钮通过 `setBounds(workArea)` 拉伸窗口；系统标题栏双击则先进入原生最大化，再被 `maximize` 事件立即 `unmaximize()`。这会逆转系统动画，也让系统状态、还原尺寸和持久化状态不同步。

现在按钮、标题栏双击及系统最大化统一使用原生状态和 `getNormalBounds()`，移除反向转换。构造窗口后重新应用保存的外部尺寸，避免 Windows 在缩放 DPI 下把初始隐藏边框累计到下次恢复尺寸。材质刷新直接重用 Acrylic，不先切换到 `none`。

Electron 33 的无边框最大化会增加隐藏边框并裁剪客户区；直接清除裁剪又会把材质画到相邻显示器。Windows helper 保留 `WS_MAXIMIZE` 与系统还原记录，仅在最大化时移除非客户区边框并匹配当前显示器工作区，还原后恢复原边框。采用 DPI 感知坐标及 `SWP_NOSENDCHANGING`，避免 Chromium 在定位过程中重新加入缓存边框。helper 仍验证 HWND 所属 PID，不访问其他应用窗口。

实现为项目独立代码；仅查阅 Electron 33.4.11 官方代码的行为说明，没有复制第三方实现：
https://github.com/electron/electron/blob/v33.4.11/shell/browser/ui/win/electron_desktop_window_tree_host_win.cc

## 验证

- 420 项测试、TypeScript 类型检查、许可检查通过。
- `scripts/verify-window-controls.cjs` 在隔离配置下运行真实生产主进程、preload、Vue 界面，通过实际按钮和 Windows 标题栏/系统消息验证最大化与还原。
- 本机两块显示器均为 125% 缩放，包含负坐标显示器；验证工作区边界、持久化普通尺寸、快速往返切换。
- 材质探针仅采集自建窗口内的小块桌面合成像素；测试窗口忽略鼠标输入，防止用户正常拖动干扰。未激活窗口会记录状态，不把 Windows 非活动材质误判为故障。
- Windows 便携 EXE、ZIP 启动与 SHA256 由发布验证脚本单独核验。Mac 沿用现有原生红绿灯与材质，不改平台行为。

运行（Windows）：先 `npm run build`，清除测试子进程的 `ELECTRON_RUN_AS_NODE`，用 `node_modules/electron/dist/electron.exe scripts/verify-window-controls.cjs`；结果写入 `out/window-controls-proof.json`。测试仅关闭自己创建的应用进程，配置写入独立临时目录。

设置 `KAMUCL_WINDOW_REOPEN=1` 可验证已保存最大化状态的重新打开及恢复尺寸。

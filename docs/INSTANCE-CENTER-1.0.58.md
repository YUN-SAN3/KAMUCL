# 实例中心与诊断（1.0.58）

入口：首页实例卡片菜单、游戏版本已安装列表的“管理实例”。详情提供概览、存档、截图、备份、诊断。后台操作保存提交时的根目录和版本 ID。

## 文件与恢复

- 复制为新隔离实例，展开继承链，独立复制玩家文件、模组启停和锁定状态。默认包含存档，不包含截图；共享目录显示复制范围。
- 手动实例备份包含玩家文件、合并后的版本元数据及客户端；不包含共享 libraries、assets、Java 和日志。单独支持存档备份与 ZIP 导出。
- 模组替换、必要前置安装、批量启停、整合包覆盖前保存保护记录。自动保留最近五条；手动记录不自动清理。
- 备份位于启动器 userData/instance-backups，按实际游戏目录区分，使用格式版本、相对路径、大小、SHA256 清单。原始截图和存档不上传。
- 默认恢复成新副本。覆盖普通隔离实例或同名存档需要勾选确认，并先创建手动备份；共享和自定义目录的实例只允许新副本恢复。
- 流式复制/压缩、暂停/取消、空间检查、链接拒绝、源文件变动检查与暂存提交。回退失败保留原始文件并显示保留路径。相关游戏运行时拒绝修改，不终止进程。

## 本地诊断

- 检查 Java、本体、库、资源索引及资源对象。只有验证后的下载文件可以替换损坏文件；失败保留原文件。
- 每个游戏启动会话使用 UUID 日志目录。只读取相同版本与实际目录的最新可识别会话，旧共享日志不参与推断；启动准备失败也保存上下文。
- 规则覆盖 Java/参数、依赖、重复与兼容性、内存、权限、磁盘、图形初始化。显示证据和可信程度，不把堆栈中的任意模组认定为原因。
- Java 修改仅作用于当前实例。明确关联的冲突文件由玩家勾选确认停用，保护记录支持恢复。
- 必要前置需由本地文件哈希精确定位社区版本，再解析全部必要依赖；不能完整确认时仅说明原因，不猜测安装。玩家确认后只补充依赖，不替换原模组或更改其锁定。
- 显卡问题提供 NVIDIA、AMD、Intel 官方入口，不修改驱动。启动器自身故障保留原日志流程。

## 验证

- `npm test`：386 项通过，包括新增备份哈希/篡改、取消、源变化、自动保留、独立复制、锁定状态、新副本和覆盖恢复、中文路径、运行占用、目录链接拒绝、日志会话隔离、精确前置及修复失败回退。
- `npx tsc --noEmit`、`npm run build`。
- 构建后，在清除 ELECTRON_RUN_AS_NODE 的环境中运行 Electron `scripts/verify-instance-center-ui.cjs`：生产 renderer 配合隔离 IPC 夹具，验证入口、长列表、弹窗 Esc、浅/深色、窄窗口、截图原图/分页/另存为及无意外启动。
- Windows 便携包/ZIP：`node scripts/verify-release-1054.cjs`（自动读取当前版本）。
- Mac 原生 ARM64/Intel runner 构建 APP ZIP 与 DMG，验证签名结构、DMG 完整性及只读挂载后的实际首页启动；保留本地 ad-hoc 签名，未使用 Apple Developer ID 或公证。
- 文件事务端到端使用临时实例和 JAR 夹具；没有宣称逐一运行全部 Minecraft/加载器组合。原生应用启动证据与单元测试证据分别保存。

行为参考 ATLauncher Instance、Prism WorldListPage、Modrinth 实例详情及 PCL ModCrash；本轮使用项目现有 TypeScript/Vue 独立实现，没有复制上述项目源码。

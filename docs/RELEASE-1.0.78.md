# KAMUCL v1.0.78 — 启动时更新与加载器下载

## 更新事务

- 下载、分片合并、SHA256 校验、刷盘全部成功后，才在便携 EXE 旁写入 `.kamuclupdate`。退出不安装、不重启。
- 下一次手动启动，在创建窗口前检查并原子认领更新记录。更新助手等待本次启动进程及便携引导进程退出，再次校验包和原 EXE，使用同卷原子替换保存备份。
- 保留原 EXE 的文件名和启动参数，避免另一个同名新版文件被覆盖、旧快捷方式继续启动旧版本。
- 新版自身校验通过且窗口就绪后写入事务回执。便携外层进程提前退出、用户正常关闭不再触发“20 秒内退出即失败”的误判。
- 脱离式助手禁止继承旧启动器的系统句柄，避免旧进程退出后端口或文件句柄仍被新进程持有；有输出管道的游戏进程保留原有日志传递。
- 更新失败或助手中断后保留可用程序及备份，隔离失败记录，停止同版自动尝试；支持通过设置重新下载或准备备份恢复。备份恢复及本地包也在下次手动启动应用。
- 旧 `pending-update.json` 在版本确有更新、可信来源及公布的 SHA256 复核通过后才迁移；不会凭文件名或仅有文件就安装。
- 校验清单优先来自所选版本对应的 Release，避免发布了新版本后误用 latest 的清单导致旧版本包无法校验。

旧版 1.0.75–1.0.77 自带的退出更新逻辑不能由远端直接修补。如旧程序已循环启动，请退出旧程序并手动使用本版 EXE 一次。之后的新更新使用上述事务流程。

## 加载器下载

- 读取 Forge / NeoForge 安装器声明的远程依赖，使用现有多连接队列、镜像/官方候选、校验和缓存并行准备。空 URL 的内嵌/生成文件仍由安装器处理。
- 下载依赖和生成运行文件分开显示；生成阶段没有伪造的剩余下载时间。安装器按 Minecraft 的 Java 要求选择环境。
- Node 网络连接失败时尝试系统网络通道，保留 Range 和文件校验。最终错误包含文件、地址和网络错误代码，并保留实际失败阶段。

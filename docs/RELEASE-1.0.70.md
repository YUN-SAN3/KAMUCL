# 1.0.70 — 游戏退出与资源释放

根因证据：本机 Minecraft 26.2 / Fabric 0.19.5 / Java 25 的退出报告中，
`Description: Client shutdown from post-main` 对应的线程转储显示
`DestroyJavaVM` 与非守护 `HTTP-Dispatcher` 仍存活；模组列表含
KAMUCL Bridge 1.0.0。桥接服务从 Fabric 初始化线程直接调用
`HttpServer.start()`，因此它的调度线程阻止 JVM 自然退出。

修复：桥接 1.0.1 从守护线程启动 HTTP 服务，请求使用独立的单线程守护
执行器，保持参数修改串行。JVM 正常关闭时停止监听并清理执行器；不使用
游戏日志关键字、窗口消失或定时强制结束判断保存是否完成。

启动前仅升级完整文件内容与已发布原版一致的 1.0.0；先建立自动保护，
检查目录占用、锁定及源文件变化，再校验临时文件并原子替换。保留文件名；
禁用、自定义和锁定版本不自动改变。已运行 JVM 不受修改影响，修复在更新
启动器并完全退出旧游戏后，下一次启动时生效。

系统确认 JVM 退出时解除资源操作占用；日志管道仍继续收尾，以免丢失最终
退出证据。发送停止请求不视为退出，多开同版本仍有进程时继续保护目录。

验证：

- 424 项自动化测试、TypeScript、许可检查与生产构建。
- `verify-bridge-exit.cjs --baseline` 在独立 JVM 复现旧版不退出。
- 修复版实际 JVM 完成 800 ms 模拟保存后约 20–30 ms 自然退出；正常请求、
  鉴权、参数修改、半截请求卡住时的退出及退出后立即移动/删除 JAR 均通过。
- 升级覆盖保护失败、源文件变化、改名、禁用、锁定、运行中及重复升级。
- Mac 构建流程也执行实际 JVM 桥接退出验证。

不对第三方 MOD 自身的保存耗时或残留线程承诺固定退出时间。完整 Minecraft
世界退出未作为上述 JVM 夹具测量数据；测试不读取账号密钥或结束玩家进程。

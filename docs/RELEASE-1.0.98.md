# KAMUCL 1.0.98

修复 CurseForge 整合包导入时，文件已经在包内或存在可用备用来源，却仍要求玩家打开网页下载并手动补充的问题。

- 包内识别扩展到资源包、光影包、数据包及 Global Packs、Paxi、OpenLoader 的资源目录。按文件大小与 SHA1 匹配，保留作者的文件名、目录和禁用状态，不把缓存目录当成已安装模组。
- 缺少下载直链时，先检查所有绑定游戏目录与已校验缓存，再查询下载地址接口、Modrinth 精确副本与 CurseMaven。下载和本地复制都必须通过原清单大小及 SHA1 校验；不会用其他版本替代，也不会跳过必需文件。
- ZIP 文件按 CurseForge 项目类型安装，修复所有资源一律放进 `mods` 的问题；包内已有的全局数据包继续使用作者安排的加载路径。
- 补充文件提示不再把所有下载地址缺失一概说成“作者未开放自动下载”。所有自动来源均失败时仍保留补充入口及取消回滚。

验证使用用户提供的「方可梦：炽白真形 客户端 0.1.15-BETA」原包，Minecraft 1.21.1 / NeoForge 21.1.248。独立空目录完整安装，清单 262 个文件逐项核对大小、SHA1 和安装位置；复用包内 10 个文件，备用源自动补全 6 个模组，无需手动补充。原始 ZIP 未修改。

构建及 511 项自动检查通过，覆盖错误哈希拒收、本地改名副本复用、原文件不变、资源目录、下载接口补链、备用下载及失败回滚。Windows 成品另作完整导入、EXE / ZIP 原生启动和 SHA256 校验。详细验证记录见 [整合包导入验证](validation/modpack-1.0.98.json)。本轮验证安装完整性，没有启动该整合包进入游戏。

备用来源采用 [CurseForge 下载地址接口](https://docs.curseforge.com/rest-api/#get-mod-file-download-url) 和 [CurseMaven 公布的项目 ID / 文件 ID 坐标规则](https://cursemaven.com/#usage)，不拼接猜测的 CDN 文件地址。

更新后重新导入原包即可使用新识别流程；原来尚在等待补充的任务需取消后重新开始。只交付 Windows 版本。

# KAMUCL v1.0.79 — 模组更新与 NeoForge 修复

本次用户诊断包来自 1.0.77，记录的是 NeoForge 26.2.0.88 安装器依赖下载失败，随后启动修复再次发生 `fetch failed`；该包没有截图中 Fabric API 更新失败的具体异常。检查代码及复现后修复了以下路径。

- 模组自动更新、单项版本切换及必要前置补充采用设置中的下载源和连接数。原先事务下载未传入镜像偏好，实际始终走官方 CDN。现在国内镜像与官方候选共用既有分段、重试及哈希校验流程。
- 更新检查也按来源偏好使用主备 API；连接失败可尝试系统网络通道。
- 更新失败在条目下直接显示具体阶段和原因，提供重试；错误写入启动器日志。部分成功后刷新文件列表不再导致“正在更新”状态无法解除。
- 管理扫描显式纳入 `.jar.disabled`，检测更新、锁定和单项版本管理可以识别禁用文件。更新后仍保持禁用状态。运行时诊断及重复模组检测保留只扫描启用文件的规则。
- NeoForge 启动修复使用普通安装时的安装器镜像、校验及并行依赖准备，避免退出普通安装流程后又退回官方单路下载。

验证：官方 CDN 模拟失败而所选镜像可用时，模组更新成功；下载失败、重名冲突、源文件变化和提交失败保留旧文件，失败后可以重试。452 项自动化测试通过。

真实界面使用官方 Fabric API 0.152.1+26.2 → 0.160.0+26.2：制造目标重名，批量更新部分失败、部分成功；成功项保持禁用，冲突文件未覆盖；解除人工冲突后从界面重试成功，生成两份保护记录，并核对目标 SHA1。

与诊断包相同的 NeoForge 26.2.0.88：在独立目录调用真实启动修复流程，21.805 秒完成缺失运行库修复，依赖准备和 Java 安装器执行成功，测试用模组及存档文件内容保持完整。该计时不包含首次取得用于测试的安装器元数据，也不代表完整游戏冷安装时间。

验证使用独立临时目录及配置，不操作用户游戏或模组。网络可达性仍取决于线路及服务端状态，不保证固定运营商速度。

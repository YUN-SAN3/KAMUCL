# KAMUCL 1.0.90

修复 Windows 上多个游戏或残留游戏进程并存时，整合包可能一直停在“Discovering mod files”的启动阻塞。原来的标准输出、标准错误读取与进程退出等待长期占用共享工作线程；线程池耗尽后，游戏写日志也无法继续。

现在只读取管道中已经到达的数据，分批让出事件循环；退出等待改为非阻塞检查。保留完整日志、退出识别和关闭启动器后游戏独立运行的行为，不自动强杀已有游戏，不修改整合包的模组或配置。

## 验证

- 旧实现双进程复现：两路分别输出 1 KB 后停住，6 秒后仍未完成；修复后均完整输出 1,024,004 字节并正常退出。
- 真实 Java 进程：一个安静后台进程加两路各 5,000 条模组扫描日志，在 Node 与 Electron 44.3.0 中均约 2 秒内完成；后台进程保持运行。
- 回归覆盖后台安静进程、同时大量 stdout/stderr、中文路径、输出 SHA256 完整性和文件读写。
- 485 项自动化测试、TypeScript 检查、许可证检查与生产构建通过；仅一个后台工作线程的限制下，并发日志测试仍通过。
- Windows 便携 EXE 原生界面启动、窗口最大化/还原及窄窗口验证通过；交付包执行内容一致性与 SHA256 检查。

## 本次报告的证据范围

附件包含 Minecraft 1.21.1 / NeoForge 21.1.248 的整合包索引（358 项文件）。视频中后一次加载停留在模组发现阶段；用户确认 PCL 可进入、KAMUCL 不可进入，且可能存在残留或同时运行的游戏。已复现并修复与这一条件吻合的启动器管道死锁。

所附文本记录了另一轮已经完成主要加载的过程（ModernFix 报告 70.611 秒），不能用它证明卡住时的 Java 线程状态。本次没有在用户电脑完成该整合包进入主菜单的复验；如仍卡住，需要故障当次 KAMUCL 诊断包继续定位。

仅交付 Windows，本批不导出 Mac 安装包。

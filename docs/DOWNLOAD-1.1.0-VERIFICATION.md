# 1.1.0 下载尾段验证

验证日期：2026-09-21；基线为已发布 Windows 便携版 1.0.99，成品为 1.1.0。

## 问题与修复

1. 小文件低速连接原先只需每 15 秒收到 16 KiB 就可能长期占据下载槽。新增小文件速度窗口，仅在存在精确备用来源、剩余传输仍明显缓慢且未暂停/主动限速时切换；最后一个来源保留完成机会。
2. 分片请求曾保存镜像的最终跳转地址，后续请求持续命中同一个慢速或已过期节点。现在每次从逻辑入口重新解析，保留各分片断点及最终文件校验。
3. 全部文件严格从大到小排序会把大量小请求延迟放到尾段。现在四个工作者中有一个优先处理小文件，其余优先大文件，任一队列清空后相互接手；没有增加全局连接上限。
4. 实测发现 86 字节资源已收齐但传输连接未结束，重试从文件末尾发起 Range 导致 HTTP 416。现在按声明长度结束接收，再进行完整哈希校验；完整断点不再发起越界请求。
5. CTI 含 13,273 个覆盖配置文件，原先逐个同步创建目录、写入。现在每批最多四个文件、常规批次最多 16 MiB，超大单文件独立处理，目录创建复用；同目标条目保持顺序，取消/失败等全部写入结束后才回滚。
6. 安装器计算的未知进度此前在并行汇总中丢失，界面显示 0%。现在沿用“处理中”，配置写入显示真实文件计数，未虚构下载速度或百分比。

## 真实成品安装

每次使用新的独立配置与空游戏目录，只绑定该测试目录，BMCLAPI、16 个总连接、不限速；三个网络安装任务依次运行，不同时争抢下载带宽。真实调用安装器 Java，不启动 Minecraft、不结束用户游戏。计时包含解析、下载、校验、安装器及配置写入；原版计时还包括一次暂停/继续和安装后资源审计。

| 测试 | 1.0.99 | 1.1.0 |
| --- | ---: | ---: |
| Construct Technological Innovation 0.43 | 89.235 秒 | 57.720 秒 |
| 方可梦：炽白真形 0.1.15 BETA | 69.143 秒 | 70.917 秒 |
| Minecraft 26.3（首轮） | 49.771 秒 | 60.001 秒 |
| Minecraft 26.3（反向顺序复测） | 48.061 秒 | 47.798 秒 |

CTI 总耗时减少约 35.3%；覆盖配置写入至完成从约 15.1 秒降至 7.7 秒。方可梦总耗时没有改善（约增加 2.6%），但整合包文件从 90% 到完成由 39.657 秒降至 28.165 秒。不能把尾段改善描述成所有整包固定倍速。

原版首轮新版比旧版多约 10.2 秒，其中获取版本信息阶段为 9.545 秒，旧版为 1.196 秒，相差约 8.35 秒；资源下载阶段约 48 秒与 46 秒。随后按“新版→旧版”顺序各重做一次空目录安装，47.798 秒与 48.061 秒基本持平，不能据此宣称原版整体显著提速，也不能只展示更快的一轮。

这是一轮真实网络对照，不是统计学稳定吞吐基准：源站/CDN 缓存与路由不可控，后台构建、压缩及磁盘负载也可能影响时间。开发候选版 CTI 另一次成功为 69.736 秒；首轮候选测试曾触发上述 416，修复并加入回归测试后重新构建成品测试，不把失败轮隐藏或计作成功。

独立于安装过程的校验结果：

- CTI：清单 269 个文件的大小与 SHA1、3,364 个唯一游戏资源、96 个运行库及游戏本体全部正确；没有手动补充请求。
- 方可梦：清单 262 个文件的大小与 SHA1、3,888 个唯一游戏资源、106 个运行库及游戏本体全部正确；没有手动补充请求。
- 原版：四轮均完成并检查本体、资源索引与 5,147 项游戏资源；暂停/继续操作通过。

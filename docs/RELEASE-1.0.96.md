# KAMUCL 1.0.96

2026-09-21 15:44 · Windows x64

修复版本下载时大量小资源长期等待慢节点的问题。批量下载先用实际文件比较已配置来源的响应与传输表现，之后优先使用更快的来源，不额外重复下载测速文件。仅选择官方源时不加入镜像。

- 有准确备用地址时，首响应等待达到 2.5 秒即可换源；最后一个来源保留原等待与重试能力。
- 大文件提前调度，较大的文件使用更合适的分片大小，减少跳转、建连和分片合并开销；原有断点仍可恢复。
- 资源索引、资源文件、带哈希的依赖库可从其他已绑定游戏目录校验后复制。缓存文件和目标文件独立，损坏缓存回退网络下载。
- 保留文件大小与哈希校验、暂停、取消、用户连接数与限速、服务端 Retry-After 冷却，以及安装失败保护。

## 实测

同一台电脑、同一网络，顺序下载 Minecraft 26.3 的完整资源集。两轮均为全新空目录、16 并发、不限速、BMCLAPI 设置及官方备用地址；不使用本地缓存。

| 总大小 | 461.29 MiB | 461.29 MiB |

本轮实测相对旧版约 **2.65 倍速度，耗时减少 62.3%**。这是资源下载阶段的一组实际网络测量，包含下载器内部校验，不包含之前获取元数据和之后的独立复核。网络线路与 CDN 调度会波动，不能视为所有用户的固定提升。

用户视频的最快参照是 PCL 导入 Mechanomania，而本轮基准是 26.3 资源集；视频中各启动器的缓存状态未确定。**尚未证明达到 PCL 的两倍，不以这组数据替代该目标的验收。**

原始摘要见 [下载测试记录](performance/download-1.0.96.json)。可通过 `scripts/benchmark-downloads.cjs` 在独立目录重复旧提交与当前源码的冷缓存测试；使用 `scripts/verify-download-gui.cjs` 验证实际便携 EXE 的安装流程。
